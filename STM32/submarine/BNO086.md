# Waterboard BNO086 bring-up

The BNO086 uses SPI1: PA5 SCK, PA6 MISO, PA7 MOSI, PA4 active-low CS,
PA10 active-low INTN, and PA12 active-low WAKE/PS0. RESET is pulled high
and is not controlled by the MCU. Board wiring must select SHTP SPI mode
(PS1 and PS0 high at sensor reset, BOOTN high). PA12 starts high in firmware;
the board must also establish the correct boot level before firmware starts.

SPI1 uses mode 3, 8-bit MSB-first transfers and APB2 / 64, approximately
1.406 MHz with the existing 90 MHz APB2 clock. The other SPI1 chip select,
PB2, starts high to prevent bus contention. Any future driver sharing SPI1
must serialize access and restore each device's SPI settings before transfer.

The CubeMX `.ioc` contains the SPI/GPIO changes. The HAL owns the
EXTI15_10 handler and enables its IRQ; do not generate a second handler.
TIM5 is reserved for its wrapping 1 MHz timestamp counter and initialized
by the HAL, independently of the motor timers. It assumes the existing
APB timer clock configuration (TIMPRE at its default).

## First board test

1. Open `submarine` in STM32CubeIDE and refresh the project. Regenerate the
   build makefiles with an IDE build so the new `Core/Src` files are included.
   The checked-in `Debug` makefiles are stale and include an old Windows
   linker path; they are not the build definition to maintain.
2. Build and flash the firmware. `main` calls `bno086_init()` before starting
   DShot and calls `bno086_service()` in its existing loop.
3. Inspect these globals with the debugger:
   - `bno086_init_done`: zero until initialization returns, one afterward.
   - `bno086_init_stage`: 0 not started, 1 opening, 2 setting callback,
     3 reading product IDs, 4 configuring reports, 5 running. On failure the
     stage stays at the failed operation.
   - `bno086_status`: zero means initialization/configuration succeeded.
     Its initial value is -1, so check `init_done` before interpreting it.
   - `bno086_hal_diag`: retained transport error, HAL SPI status, last INTN
     level, falling-edge count, transfer count, and last received header.
     A last error of -6 means readiness timed out; -4 means SPI failure or
     an invalid packet length. Inspect `spi_status` and `rx_header` to
     distinguish them. The header is updated only after a successful read.
   - `bno086_product_ids`: device identification returned by the sensor.
   - `bno086_report_count`: should increase at roughly 50 reports/second.
   - `bno086_latest`: decoded rotation vector, including quaternion fields
     `un.rotationVector.real/i/j/k`, timestamp and accuracy status.
4. Rotate the board and confirm the quaternion changes. The report count
   is the freshness indicator; a stored quaternion alone does not show that
   communication is still running. No UART output is added.

The implementation sends an executable-channel software reset on open.
After sensor reset notifications it restores the 50 Hz rotation-vector report
outside the SH-2 callback. Hardware reset and holding the sensor in reset on
close are unavailable with this wiring. If the sensor cannot accept software
commands, power-cycle the board. Initialization failure is exposed to the
application and does not repeatedly reset the sensor from the motor loop.

Transfers are blocking, with bounded SPI/readiness timeouts of 20 ms each.
A successful 1024-byte transfer takes about 6 ms at this clock. This first
bring-up driver can therefore delay the existing motor loop; assess timing
on the board before relying on that loop for control. An interrupt/DMA
transport can follow once communication is verified.

## Validation

Run `python3 tests/test_bno086_hal.py` from this directory. The host test
uses a mock STM32 HAL to check packet framing, CS lifetime, full-duplex RX
preservation during writes, zero padding, malformed/oversized lengths,
buffer limits, SPI errors and readiness timeouts. It does not verify sensor
behavior or electrical timing.

The firmware was also compiled and linked using STM32CubeIDE's ARM GCC,
all project C sources, the configured HAL drivers and the project's linker
script. Physical-board validation is still required.
